# Scientific Experiment Lifecycle

IUVFES treats an experiment as an auditable chain of evidence, not only as a simulator run.

```text
DESIGN
  ↓
READY
  ↓
RUNNING
  ↓
OBSERVATIONS + EVENTS
  ↓
RAW DATASET
  ↓
VALIDATION
  ↓
DIGITAL TWIN COMPARISON
  ↓
ANALYSIS
  ↓
FINDING
  ↓
REVIEW
  ↓
PUBLICATION DATASET / JOURNAL REPORT
```

## Evidence classes

`EXPERIMENTAL` is measured or manually recorded laboratory evidence.

`SIMULATION` is generated by a model and must retain model/configuration/version references.

`DERIVED` is calculated from other data and must retain its input references.

`AI_ANALYSIS` is an interpretation or recommendation and must not silently become experimental evidence.

## Reproducibility record

A published finding should be traceable to:

- experiment ID;
- raw dataset manifest and SHA-256;
- instrument identity and calibration;
- processing/analysis version;
- Digital Twin model/configuration version, if used;
- application Git commit;
- researcher/reviewer identity;
- assumptions and limitations.

## Data integrity

Sensor observations are append-oriented. Corrections create new records or derived datasets. The original observation remains addressable. Large raw payloads should be kept in object storage with a content hash in the database.

## Safety boundary

The simulator is a research and engineering tool. It must not be represented as controlling a real reactor or laboratory machine unless a separate, validated control/instrumentation layer with appropriate hardware safety interlocks, authorization and operational procedures exists.
