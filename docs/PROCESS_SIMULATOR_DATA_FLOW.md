# IUVFES Process Simulator — Data Flow Contract

## Purpose

This document freezes the visual data contract for the Process Simulator. The UI is a presentation layer over the existing closed-loop engine. It must not create a second physics model.

## Runtime chain

```text
Experiment input
  -> closedLoop.create
  -> closedLoop.start
  -> closedLoop.step (dt = 1 s in current UI)
  -> ClosedLoopSimulationEngine
  -> CausalFrame
  -> ProcessSimulator state
  -> ProcessMachine3D / instrumentation / graphs / timeline
  -> ScientificRunRecorder
  -> dataset / provenance / report / print
```

## Hardware diagnostics mapping

`HardwareDynamicsDiagnostics` currently exposes:

- connectedVolumeL
- pipeVolumeL
- vacuumConductanceM3h
- effectivePumpCapacityM3h
- thermalMassKjPerK
- heatingPowerKw
- coolingPowerKw
- leakRateMbarPerSecond
- ultrasonicEffectivePowerKw
- ultrasonicPowerDensityWPerL
- hardwareWarnings
- coldTrapTemperaturesC[4]
- coldTrapHeatLoadKw
- coldTrapCondensationCapacityKgPerSecond
- coldTrapStageCondensedWaterKg[4]

The four cold-trap temperatures are hardware/model diagnostics. They are not laboratory measurements unless a separate laboratory dataset says so.

## Evidence separation

The UI must keep these origins distinct:

- `MEASURED`: laboratory/real instrument evidence.
- `SIMULATION` / `DERIVED`: generated by the closed-loop model.
- `ASSUMED`: explicit engineering assumption.
- `DATASHEET_REQUIRED`: missing physical specification.
- `UNKNOWN` / `DATA GAP`: unavailable information.
- `VALIDATED`: comparison supported by an appropriate laboratory dataset.

The Process Simulator must never convert a simulated value into a measured value.

## Animation rules

Animation is a visualization of state, not an independent process model.

- No effective command -> no corresponding process-flow animation.
- Heater active -> thermal visual may intensify using sensor temperature and effective heater command.
- Vacuum pump active -> vacuum-line flow may animate.
- Extraction/condenser active -> vapor-line flow may animate.
- Cooling active -> cooling-line flow may animate.
- Safety fault -> safety visual overrides normal visual state.
- Pause -> freeze process animation at the last frame.
- Stop/reset -> follow engine state; do not invent a reset trajectory.

## Current UI gaps to close

1. ProcessMachine3D now renders four cold-trap objects and accepts four diagnostic values, but ProcessSimulator still needs to pass `hardwareDiagnostics` into the machine view.
2. The current realtime chart is temperature-only; pressure, vacuum, and ultrasonic traces should be added from the same `frames` array without creating synthetic data.
3. The current ProcessEventTimeline derives stage/alarm events from frames; controller/effective-command changes can be added as secondary causal events without replacing the existing stage journal.
4. ScientificRunRecorder already records causal frames and creates the simulation dataset manifest; its provenance labeling must remain intact.

## Non-goals

This UI layer must not:

- change the scientific equations;
- replace PID coefficients;
- bypass safety interlocks;
- fabricate laboratory measurements;
- silently fill UNKNOWN values;
- create a separate physics simulation inside React.
